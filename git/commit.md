# 커밋 관리 규칙

> 상태: 확정 (2026-07-26)
> 메시지 형식은 `git/commit-message.md`를 따른다.

## 커밋 단위

- 커밋 하나에는 하나의 논리적 변경만 담는다. 독립적으로 이해하고
  되돌릴 수 있는 단위를 만들기 위함이다.
- 각 커밋은 가능한 한 빌드하고 테스트할 수 있는 상태로 남긴다.
- rename·포맷팅·파일 이동 같은 기계적 변경은 동작 변경과 분리한다.
  의미 있는 diff가 기계적 변경에 묻히지 않게 하기 위함이다.
- `WIP`, `fixup!` 커밋은 PR을 병합하기 전에 정리한다.
- 여러 커밋을 squash할 때도 서로 다른 논리적 변경까지 하나로 합치지 않는다.

## 공유된 변경 되돌리기

- `main`, `develop`에 반영된 변경은 reset으로 지우지 않고 revert한다.
  공유 히스토리를 보존하면서 취소 사실도 기록하기 위함이다.
- 병합된 PR 전체를 취소할 때는 개별 커밋이 아니라 merge commit을
  revert한다.
- 아직 다른 사람과 공유하지 않은 개인 작업 브랜치만 reset·rebase로
  정리할 수 있다.
- revert한 변경을 다시 적용할 때는 기존 히스토리를 고치지 않고 새 커밋이나
  새 PR로 진행한다.
