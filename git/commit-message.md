# 커밋 메시지 규칙

> 상태: 확정 (2026-07-11)

## 형식: Conventional Commits

```text
타입(스코프): 제목

본문 (선택)
```

- 로그만 보고 변경의 성격을 알 수 있고, 타입 기반 검색·체인지로그
  자동화가 가능하기 때문에 채택.
- **타입은 영어, 제목·본문은 한국어**로 쓴다. 주 독자가 본인이므로
  가장 빨리 쓰고 정확히 읽히는 언어를 쓰되, 타입은 도구 호환성과
  검색성을 위해 표준 영어 키워드를 유지한다.

## 타입

| 타입 | 용도 |
|---|---|
| `feat` | 기능 추가·변경 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변화 없는 구조 개선 |
| `perf` | 성능 개선 |
| `test` | 테스트 추가·수정 |
| `docs` | 문서만 변경 |
| `style` | 포맷팅 등 코드 의미에 영향 없는 변경 |
| `chore` | 빌드, 의존성, 설정 등 그 외 잡무 |

- 스코프는 선택. 변경 영역을 좁혀줄 때만 쓴다 — `fix(auth): ...`

## 제목

- 50자 이내, 마침표 없이.
- "~한다/~했다"가 아니라 **"~추가", "~수정", "~제거"처럼 명사형**으로
  끝낸다. 짧고 로그에서 스캔하기 쉽다.
- 제목만 보고 무엇이 바뀌었는지 알 수 있어야 한다.

## 본문

- **"왜"를 기록한다.** 무엇이 바뀌었는지는 diff가 말해주므로, 본문에는
  이유·배경·트레이드오프를 남긴다.
- 자명한 변경이면 본문은 생략한다.

## 깨지는 변경 (breaking change)

- 타입 뒤에 `!`를 붙이고, 본문에 `BREAKING CHANGE:`로 내용을 명시한다.

```text
feat(api)!: 응답 envelope 구조 변경

BREAKING CHANGE: 모든 응답이 code/message/result로 래핑된다.
기존 클라이언트는 result 언래핑이 필요하다.
```

## 예시

```text
feat: 주문 취소 기능 추가

fix(auth): 만료 토큰 갱신 시 무한 루프 수정

refresh 요청이 401을 받으면 다시 refresh를 시도해서 루프가 생겼다.
401 응답에서는 재시도 없이 로그아웃하도록 변경.

docs: README에 설치 방법 추가

chore: eslint 규칙에 snake_case 변수 허용 추가
```
