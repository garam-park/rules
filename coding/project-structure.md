# 프로젝트 구조 규칙

> 상태: 확정 (2026-07-11)
> 디렉터리 이름 표기는 `naming.md`(kebab-case, Python은 snake_case)를 따른다.

## 레이아웃: 도메인형

- **기능(도메인)별로 묶고, 그 안에 계층을 둔다.** 기능 하나를 고칠 때
  한 폴더만 보면 되고, 기능 삭제가 폴더 삭제로 끝난다.

```text
src/
├── orders/
│   ├── order-controller.ts
│   ├── order-service.ts
│   ├── order-repository.ts
│   └── order-model.ts
├── users/
│   └── ...
└── shared/
    └── ...
```

- 파일 이름에 도메인과 역할을 함께 쓴다 (`order-service.ts`).
  에디터 탭·검색에서 `service.ts` 여러 개가 구분되지 않는 문제를 피한다.

## 계층: controller → service → repository

| 계층 | 역할 |
| --- | --- |
| controller | 진입 경계. 요청 파싱·검증, 응답 변환. 비즈니스 로직 없음 |
| service | 비즈니스 로직. 트랜잭션 경계 |
| repository | 저장소 접근. 쿼리만, 판단 없음 |

- model(엔티티·스키마)은 도메인 폴더 안에 함께 둔다.
- 이보다 복잡한 구조(헥사고날 등)는 필요가 증명되기 전에는 쓰지 않는다.

## 의존 방향: 한 방향만, 건너뛰기 금지

- **controller → service → repository 방향만 허용한다.**
  - 역방향 금지: service가 controller를, repository가 service를 모른다.
  - 건너뛰기 금지: controller가 repository를 직접 호출하지 않는다.
    "단순 조회라서"라는 예외를 만들면 service 경유 여부가
    케이스바이케이스가 된다. 규칙은 기계적이어야 지켜진다.
- **다른 도메인은 service를 통해서만 접근한다.**
  `orders`가 사용자 정보가 필요하면 `user-service`를 호출한다.
  다른 도메인의 repository·model에 직접 접근하지 않는다 —
  도메인 내부 구조를 바꿔도 다른 도메인이 깨지지 않게 하기 위함.

## 공통 코드: shared/ + 입장 제한

- 여러 도메인이 쓰는 코드는 `shared/`에 둔다. 단 **입장 조건**이 있다:
  **도메인 지식이 없는 것만** — 로거, 날짜 유틸, 공통 에러 타입,
  envelope 직렬화 등.
- 도메인 로직이 shared로 새어 나가는 것을 금지한다. "orders와 users가
  둘 다 쓰니까 shared로"가 아니라, 두 도메인이 쓰는 도메인 로직이라면
  그것은 셋째 도메인이거나 한쪽 service의 공개 API다.
- `shared/`는 도메인을 import할 수 없다 (의존 방향: 도메인 → shared 단방향).

## 한시적 계층: transitional/에 모으고 삭제 조건을 적는다

- 마이그레이션·하위 호환처럼 **처음부터 지우는 것이 목표인 코드**는 여러
  도메인의 형식을 알아도 도메인별로 쪼개지 않고 `src/transitional/`에
  한 모듈로 모은다.
  - 쪼개면 규칙은 지켜지지만, 통째로 지우는 것이 목적인 코드가 도메인마다
    흩어진다. "예전 데이터는 이제 없다"고 판단한 시점에 삭제가 어려워진다.
  - `shared/`에는 넣지 않는다. 도메인 지식이 있는 코드가 들어가면
    "도메인 지식 없는 것만"이라는 입장 조건이 무너진다.
- **파일이 하나여도 폴더를 만든다.** 도메인 폴더와 나란히 놓여야 구조만 보고
  "여기는 지울 코드"임을 알 수 있고, 삭제가 폴더 삭제로 끝난다.

```text
src/
├── orders/
├── users/
├── transitional/
│   ├── storage-compat.ts       # 예전 저장 형식 → 현재 형식
│   └── storage-compat.test.ts
└── shared/
```

- **도메인이 이 모듈을 import하는 것은 허용하되, 이 모듈은 도메인의 타입만
  참조한다.** service·repository를 호출하지 않는다. 동작을 부르기 시작하면
  도메인 로직이 한시적 계층으로 새고, 나중에 지울 때 로직까지 함께 사라진다.
- **파일 맨 위에 왜 있는지와 언제 지울 수 있는지를 적는다.** 삭제 조건이
  적히지 않은 모듈은 한시적 계층이 아니다 — 그냥 잘못 놓인 코드다.

```typescript
/**
 * 저장된 JSON을 현재 필드 이름으로 읽기 위한 호환 계층 — 순수 함수만 둔다.
 *
 * 작명 규칙을 적용하기 전 camelCase로 저장된 데이터가 기기에 남아 있으므로,
 * 읽을 때 예전 키를 현재 키로 옮긴다. 쓰기는 항상 현재 이름으로 하고, 한 번
 * 다시 저장되면 예전 키는 사라진다. 기기에 예전 데이터가 없다고 볼 수 있게
 * 되면 이 모듈과 호출부를 함께 지운다.
 */
```

- **테스트를 함께 남긴다.** 예전 형식은 시간이 지나면 재현하기 어려워져,
  테스트가 "무엇을 지원했는지"의 유일한 기록이 된다. 삭제해도 되는지는
  그 기록을 보고 판단한다.
- 저장소·네트워크를 import하지 않는 **순수 함수(예전 값 → 현재 값)로 만든다.**
  mock 없이 입력과 출력만 검증할 수 있고, 지울 때 호출부만 걷어내면 된다.
